# Архитектура и руководство пользователя: HTML Визуализация SAR

Интерактивная аналитическая система для пространственного анализа, фильтрации спекла и валидации радиолокационных изображений Sentinel-1 (C-диапазон, IW GRD) и сверхвысокого разрешения Capella Space.

---

## 1. Структура каталога

Система полностью изолирована в каталоге `HTML Визуализация/`. Внутреннее разделение исключает смешивание исходных данных, исполняемого кода, весов моделей и генерируемых отчетов:

```text
HTML Визуализация/
├── html/
│   └── index.html               # Единственный канонический автономный HTML-интерфейс
├── данные/
│   ├── s1_*.nc                  # Исходные двухполяризационные растры Sentinel-1 (NetCDF)
│   ├── sar_2025_0_0.nc          # Полноразмерный композитный растр (NetCDF)
│   ├── sar_2025_0_0.tif         # Геопривязанный растр GeoTIFF
│   └── paper_results/           # Эталонные изображения из научных статей (arXiv)
├── результаты_фильтрации/
│   ├── benchmark_results/       # Метрики бенчмаркинга алгоритмов (JSON, CSV, графики)
│   ├── forest_top_pipelines.json
│   ├── massive_experiments_results.json
│   └── pipeline_search_results.json
├── веса/
│   └── *.pth                    # Обученные контрольные точки нейросетей (39 файлов)
├── тесты/
│   ├── test_extensibility.py    # Проверка регистрации фильтров, полигонов и форматов
│   ├── check_html.py            # Валидация сборки index.html и отсутствия дубликатов
│   ├── check_html_bench.py      # Валидация структуры тестовых эталонов
│   └── test_js_filters.js       # Тестирование клиентских фильтров JavaScript
└── код/
    ├── config.py                # Конфигурация путей, спецификация и реестр сцен
    ├── filter_registry.py       # Реестр FilterRegistry, расчет метрик, WebP сжатие
    ├── filters_suite.py         # Реализации 27 алгоритмов фильтрации

    └── sar_server.py            # Локальный GPU-сервер для интерактивных каскадов
```

## 2. Системные требования и зависимости

Для сборки автономного отчета и запуска локального сервера необходим Python 3.10+ с пакетами:

```bash
pip install torch torchvision numpy scipy rasterio pillow matplotlib
```

Аппаратные требования:
* Генерация статического HTML: CPU (x86_64), от 8 ГБ RAM.
* GPU-ускорение (при наличии): CUDA 11.8+ / 12.X, PyTorch с поддержкой cuDNN. При отсутствии видеокарты все алгоритмы автоматически переключаются на расчет на центральном процессоре (CPU fallback).

## 3. Переменные окружения

Все системные пути и параметры вычисляются динамически относительно расположения файлов. Переопределение осуществляется через переменные среды:

| Переменная окружения | Значение по умолчанию | Назначение |
|---|---|---|
| `SAR_ROOT_DIR` | Корневая директория репозитория | Базовый каталог репозитория |
| `SAR_DATA_DIR` | `HTML Визуализация/данные` | Каталог входных файлов `.nc`, `.tif`, `paper_results` |
| `SAR_DATA_CACHE` | `temp/data_cache` | Каталог кэшированных массивов `.npz` |
| `SAR_WEIGHTS_DIR` | `HTML Визуализация/веса` | Каталог весов обученных нейросетей (`.pth`) |
| `SAR_RESULTS_DIR` | `HTML Визуализация/результаты_фильтрации` | Каталог сохранения результатов и сводок |
| `SAR_HTML_DIR` | `HTML Визуализация/html` | Каталог вывода файла `index.html` |
| `SAR_WEBP_QUALITY` | `70` | Степень сжатия WebP (целое число от 1 до 100) |
| `SAR_BENCHMARK_RUNS`| `3` | Число повторных проходов для замера времени `time_ms` |
| `SAR_DEFAULT_BASEMAP`| `esri` | Оптическая подложка по умолчанию (`esri`, `seasonal_gibs`, `osm`) |

## 4. Этапы работы генератора (`build_full_benchmark.py`)

Генератор запускается командой:
```bash
python "HTML Визуализация/код/build_full_benchmark.py"
```

Код последовательно выполняет 7 детерминированных этапов:

1. **Инициализация окружения**: сканирование каталогов данных и весов, выбор устройства (`cuda` или `cpu`).
2. **Опрос реестра алгоритмов**: из `FilterRegistry` извлекается список всех зарегистрированных методов (27 алгоритмов).
3. **Итерация по сценам `SCENES_REGISTRY`**:
   * Для каждого полигона вызывается `load_scene_rasters(scene_spec, temporal_key)`.
   * Модуль автоматически читает реальные данные из доступного формата: `.npz`, `.nc` (через субдатасеты `VV` и `VH`), либо `.tif`.
   * При наличии логарифмических данных в дБ ($mean < 0$ дБ) выполняется перевод в линейную шкалу мощности: $I = 10^{dB / 10}$.
4. **Фильтрация и бенчмаркинг**:
   * К массивам $VV$ и $VH$ применяется оператор `spec.execute(vv, vh)`.
   * Измеряется точное аппаратное время выполнения на целевом процессоре (`time_ms`).
   * Вычисляются спектральные каналы: $VV_{dB} = 10 \log_{10}(VV)$, $VH_{dB} = 10 \log_{10}(VH)$, $Ratio_{dB} = VV_{dB} - VH_{dB}$, и растр невязки $r = I / \hat{R}$.
5. **Расчет математических метрик качества**:
   * **ENL** (Equivalent Number of Looks):
     $$\mathrm{ENL} = \frac{\mu^2}{\sigma^2}$$
     Вычисляется на однородном участке размером $30\% \times 30\%$ от центра кадра.
   * **EPI** (Edge Preservation Index):
     $$\mathrm{EPI} = \frac{\sum |\nabla I_{\mathrm{filt}}|}{\sum |\nabla I_{\mathrm{raw}}|}$$
     Определяет степень сохранения высокочастотных контуров с использованием операторов Собеля.
   * **Bias (дБ)**:
     $$\mathrm{Bias} = 10 \log_{10}\left(\frac{\mu_{\mathrm{filt}}}{\mu_{\mathrm{raw}}}\right)$$
     Характеризует сохранение среднего уровня радиометрической калибровки (идеал: 0.00 дБ).
   * **SSI** (Speckle Suppression Index):
     $$\mathrm{SSI} = \frac{\sqrt{\operatorname{Var}(I_{\mathrm{filt}})} / \mu_{\mathrm{filt}}}{\sqrt{\operatorname{Var}(I_{\mathrm{raw}})} / \mu_{\mathrm{raw}}}$$
   * **SMPI** (Speckle Suppression and Mean Preservation Index):
     $$\mathrm{SMPI} = Q \cdot \frac{\operatorname{Var}(I_{\mathrm{filt}})}{\operatorname{Var}(I_{\mathrm{raw}})}, \quad Q = 1 + |\mu_{\mathrm{raw}} - \mu_{\mathrm{filt}}|$$
   * **Дисперсия отношения** $\operatorname{Var}(r)$:
     $$r = \frac{I_{\mathrm{raw}}}{I_{\mathrm{filt}}}, \quad \text{теоретический эталон для Sentinel-1: } \operatorname{Var}(r) \approx \frac{1}{L} \approx \frac{1}{4.4} \approx 0.227$$
   * **PSNR и SSIM** (при наличии многопроходного эталона Ground Truth $X^*$):
     $$\mathrm{PSNR} = 10 \log_{10}\left(\frac{\max(X^*)^2}{\frac{1}{N}\sum (X^* - I_{\mathrm{filt}})^2}\right)$$
     $$\mathrm{SSIM} = \frac{(2\mu_x\mu_y + c_1)(2\sigma_{xy} + c_2)}{(\mu_x^2 + \mu_y^2 + c_1)(\sigma_x^2 + \sigma_y^2 + c_2)}$$
6. **Сжатие в WebP base64**:
   * Растры переводятся в одноканальные и RGB-композитные WebP-изображения с качеством `WEBP_QUALITY = 70`.
   * Это уменьшает итоговый размер HTML-файла в 7 раз по сравнению с несжатыми PNG-массивами при сохранении 100% автономности без сервера.
7. **Инъекция данных и сохранение**:
   * Сформированная структура сериализуется в JSON и внедряется в `html_template.py` в точки `__DATA_JSON__` и `__FILTER_METADATA_JSON__`.
   * Результат записывается строго в один файл: `HTML Визуализация/html/index.html`.

## 5. Добавление новых компонентов (Масштабирование)

Архитектура построена на слабой связности (декуплировании). Для добавления новых алгоритмов, полигонов или дат не требуется изменять код верстки, JavaScript или серверную диспетчеризацию.

### 5.1. Добавление нового фильтра в 1 шаг

Откройте файл `HTML Визуализация/код/filters_suite.py` и добавьте функцию с декоратором `@register_filter`:

```python
    default_kwargs={"window_size": 7, "threshold": 0.15},
    is_gpu=False,
    description="Поточечная адаптивная фильтрация спекла."
)
def filter_my_custom(vv: np.ndarray, vh: np.ndarray, window_size: int = 7, threshold: float = 0.15):
    # vv и vh - двумерные матрицы float32 линейной мощности
    # Алгоритм фильтрации:
    vv_filtered = np.copy(vv)     # расчет нового массива
    vh_filtered = np.copy(vh)     # расчет нового массива
    return vv_filtered, vh_filtered
```

После добавления фильтр автоматически:
* Включается в расчет статического бенчмарка в `build_full_benchmark.py`.
* Появляется в выпадающих списках слоя A и слоя B в HTML-интерфейсе.
* Добавляется в интерактивный конструктор каскадов с указанными параметрами `default_kwargs`.
* Становится доступен для вызовов через REST API сервера `sar_server.py`.

### 5.2. Добавление нового полигона (локации)

Откройте `HTML Визуализация/код/config.py` и добавьте вызов `register_scene`:

```python
register_scene(
    scene_id="baikal",
    title="9. Озеро Байкал (Святой Нос, 53.5°N, 108.8°E)",
    desc="Ледовый покров и открытая вода, трещины ледовых полей в C-диапазоне.",
    center=[53.50, 108.80],
    zoom=11,
    bbox=[108.60, 53.40, 109.00, 53.60],
    # Файл данных: поддерживаются .nc, .tif, .npz
    # Если не указан, файл ищется автоматически как s1_baikal.nc или raw_baikal.npz
    file_path="HTML Визуализация/данные/s1_baikal.nc"
)
```

Система автоматически:
* Определит формат файла.
* Загрузит поляризации $VV$ и $VH$.
* Сформирует картографические границы в Leaflet.
* Добавит локацию в селектор полигонов интерфейса.

### 5.3. Добавление произвольных дат и временных рядов

Для добавления произвольных дат снимков конкретного полигона передайте словарь `custom_dates` в `register_scene`:

```python
register_scene(
    scene_id="forest",
    title="Бореальный лесной массив",
    desc="Мониторинг сезонных изменений.",
    center=[56.50, 35.80],
    zoom=13,
    bbox=[35.75, 56.46, 35.85, 56.54],
    custom_dates={
        "2024-06-01": {"file": "HTML Визуализация/данные/forest_2024_06_01.nc"},
        "2024-09-15": {"file": "HTML Визуализация/данные/forest_2024_09_15.tif"},
    }
)
```

Интерфейс динамически создаст пункты в селекторе сезонов с префиксом `📅 Временной срез: YYYY-MM-DD` и синхронизирует оптическую подложку NASA GIBS Terra на выбранный день.

## 6. Локальный интерактивный сервер (`sar_server.py`)

Сервер предназначен для динамического вычисления произвольных пользовательских каскадов фильтрации на GPU в реальном времени.

Запуск сервера:
```bash
python "HTML Визуализация/код/sar_server.py" 8080
```

Архитектура API сервера:
* `GET /api/filters`: возвращает метаданные всех доступных в `FilterRegistry` алгоритмов и их аргументов по умолчанию.
* `GET /api/scenes`: возвращает список зарегистрированных полигонов и их географические координаты.
* `POST /api/pipeline`: принимает JSON с описанием каскада этапов:
  ```json
  {
    "mode": "gis",
    "target_id": "forest",
    "season": "spring",
    "stages": [
      {"op": "ftv", "kwargs": {"alpha": 1.25, "K": 11}},
      {"op": "resnet", "kwargs": {}}
    ],
    "layer": "rgb"
  }
  ```
  Сервер производит расчет на GPU, выполняет прямое вычисление метрик качества и возвращает Base64-растр для мгновенного отображения на шторке слоя B.
* `GET /`: обслуживает статическую сборку `HTML Визуализация/html/index.html`.
